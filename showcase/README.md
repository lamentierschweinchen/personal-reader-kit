# New reading

The public catalogue and six complete readers share **https://newreading.app/**. The homepage and [How it works](learn/index.html) are generated by `pages.mjs` (run `node pages.mjs` after editing copy) and use self-hosted IM Fell English, Reenie Beanie, Martian Mono and Piazzolla. [Asset provenance and licenses](ASSETS.md).

**https://read.lookatseel.com/** is the short personal-site entrance: covers open into three phone screens, then an unframed “Read it. Explore it.” page with an exact Alice passage and Rackham’s rabbit, and one Get started link to New reading. Alice is centered with a selected passage, Canetti shows a map without a reader destination, and Walden shows the house account. Native HTML keeps the text sharp. Footer links and a quiet colophon hold the context. Keep [this page](personal/index.html) separate from New reading. Its local preview is `/personal/`. Native scrolling drives the opening; reduced motion, short viewports and no JavaScript show covers and previews in normal flow. Phone controls switch the illustrations in place.

The three optional games live at `/alice/play/`, `/odyssey/play/` and `/dracula/play/`. Their original vector artwork follows the corresponding reader. Each reader has a Play entrance; the catalogue links directly to each game. Return links restore the launching route, and the reader’s worker caches the complete game. Notes and reading progress remain separate from in-memory game state.

The catalogue has no account, analytics or reading storage. Its book-and-idea form keeps a bounded draft in session storage for this tab, so the setup guide and copy controls preserve the visitor’s preferences. The draft is never placed in a URL or sent to a server; typing and manual copying still work if storage or clipboard access is blocked. Each reader uses a separate database name, service-worker scope, cache prefix and install-manifest identity under `/austen/`, `/alice/`, `/walden/`, `/two-halls/`, `/odyssey/` or `/dracula/`. Those namespaces prevent accidental collisions; they are not a security boundary against other code on the same origin. Install a reader from its own path. The landing page itself does not promise offline reading.

`build.mjs` copies only its named catalogue inputs. `readers.mjs` runs the six reader builders, compares every generated file with `examples/catalog.json`, then adapts known runtime paths and storage names. Unexpected source/output changes stop the build. Complete edition JSON and image bytes stay unchanged. Each original example still builds independently. The default kit build and personal starter remain original-samples-only.

```sh
cd showcase
npm run build
npm run dev
# With the optional Playwright runtime installed:
npm run check
# Render a candidate social image in ignored test-results, then inspect it.
npm run share-image
```

The checks cover the page at phone/tablet/desktop sizes, keyboard and no-JavaScript access, copy failure, all six readers together, and reload/chapter/companion/note editing with the server stopped. A separate check rebuilds from only `inputs.json` in a fresh temporary directory. These are developer checks, not native home-screen installation, physical iOS gestures, screen-reader acceptance or a human onboarding session.

## Hosting

The existing `lookatseel-read` Vercel project uses this `showcase` directory, `npm run build`, output `dist`, Node 24 and `node --version` as its install command. The combined deployment requires **Include source files outside the root directory** for the six reviewed sibling examples; the owner approved and enabled that setting for this project on 17 October 2026. Preview authentication remains enabled. `inputs.json` and `.vercelignore` enumerate exact required files; no private workspace, source archive, intake, notes or arbitrary example directory is admitted. Deploy the reviewed Git repository, never the surrounding Reading workspace. The stock kit's root upload list remains unchanged.

Keep `vercel.json` with the output: it applies the reader CSP, worker revalidation, stable trailing-slash entrances and the examples' noindex default. The public catalogue permits indexing. Home-screen installation is per reader, not a wrapper around the catalogue.

A host-specific homepage route serves `personal/index.html` only at `read.lookatseel.com`. It must run **before the filesystem handler**: the first live check found that a high-level rewrite ran after the existing `index.html` and left the catalogue visible. The explicit `routes` array preserves the existing headers and slash redirects, then selects the personal entrance before normal file lookup. Both domains stay on the existing project; New reading's homepage and the six reader paths keep their own files. The loopback server previews static files without emulating Vercel's host routing, so verify both actual HTTPS homepages after publishing a routing change.

The four former book hosts use explicit homepage and wildcard-path redirects. Verify the actual root response, a deep asset request, query parameters and a chapter fragment after deployment: the first live migration check found that the wildcard rule redirected deeper paths while the homepage still served the old app. A successful build alone did not establish correct routing.

The user chose a clean launch for these previously unshared examples, so this release has no old-origin data migration. General migration guidance for personalized readers remains in [DEPLOYMENT.md](../docs/DEPLOYMENT.md). A database backup cannot install an app; the guide treats backup, installation and offline verification separately.

Release evidence belongs in [STATUS.md](../docs/STATUS.md); private captures and machine receipts stay in ignored `test-results/`. Bookshop.org is an ordinary non-affiliate support link, not a claim that its purchases can be imported.
