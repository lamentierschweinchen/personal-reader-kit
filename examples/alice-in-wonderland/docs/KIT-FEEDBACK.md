# Real-book trial: Alice / Rackham / Dobson

16 October 2026. Starting kit: **v0.4.0**, commit `4c386ed521dc16f1bd08c96c3eafbdf765b4f4e7`. Project: `alice-in-wonderland`, branch `codex/alice-in-wonderland`. This is a completed local agent build of a real book, **not a completed human newcomer pilot**. No root, kit, sibling project or registry was edited by this instance. No remote, push or deployment was created.

## What worked unchanged

The dependency-free Node application and fixed output build were a practical starting point. IndexedDB storage, exact UTF-16 quotation anchors, multi-block quotations, note save/reload, conflict-safe backup merging, portable bundle integrity checks, appearance settings, navigation, explicit spoiler permissions, the service-worker cache, and the main reading/context separation were reused. The original-sample source hash gate remains intact and those sample bytes are unchanged.

The bounded EPUB tool made the correct decision: it refused this illustrated EPUB with `needs-adapter / manifest-feature` and produced **no partial edition**. The refusal exposed a real boundary rather than quietly flattening the book. The guide’s distinctions between coverage, character agreement and proofreading were useful, as were the requirements for exact passage visibility and a failed-network control.

## Passage sharing and offline annotation writes

This bounded addition reuses the coordinator’s `share.mjs` and note-editor actions. Attribution is visible before the action and includes author, title, section and edition. The helper projects only a validated quotation and those fields into a plain-text payload. It does not serialize the note, source fingerprint, raw book metadata or current URL. Sharing an invalid edition anchor is refused. Cancelling native sharing never triggers clipboard fallback. Native resolution is described as opening the share menu, not proof of delivery; unavailable share/copy APIs expose selectable text without discarding the draft.

The three new pure tests use only original writing. `tests/share-browser.mjs` uses an independently imported original verse fixture and replaces native share/clipboard APIs before loading the reader. It checks exact quotation whitespace and attribution, cancellation, failure, unsupported and missing APIs, explicit copy, complete manual fallback, saved-passage sharing, unchanged unsaved note and reading place, and refusal after a source-revision mismatch. These are synthetic device-API outcomes: no message, recipient, real clipboard write or native delivery is exercised. ## Reusable kit suggestions

1. Add a versioned media capability with explicit asset ownership, supported safe MIME types, dimensions, byte hashes, alt/caption semantics and portable-bundle behavior. Preserve an original-samples-only upstream distribution; illustrated source adapters belong in authorized projects.
2. Make the importer’s feature/coverage report richer even after an early rejection. This EPUB report stopped at the first unsupported manifest resource, so it did not itself describe all the work required.
3. Represent source layout, page references and annotations explicitly. A verse line is more than whitespace; safe line geometry and an accessible alternate can preserve both form and enlarged reading. Keep source-note explanations usable with touch and keyboard.
4. Separate public-sample configuration from product scaffolding and fixture assumptions. A project can reuse the strong reader/backup core without carrying sample-specific walk tabs or rewriting its browser acceptance harness.
5. Let a publication extension add a content-pinned provenance review for known assets and complete history, without bypassing unknown/private file checks. Decode embedded binary payloads explicitly; base64 is packaging, not a rights clearance.
6. Carry the focus scroll-event fix upstream with a focused WebKit regression. The broader image, source and typography adapter has not been proposed as a generic upstream conversion engine.

## Remaining limits and publication blockers

No destination or publication approval exists. The source catalogue says **public domain in the USA**; worldwide clearance is not asserted. Any public host/repository needs a final jurisdiction/audience/source-notice review and an audit of its exact selected files and full intended history. These project book assets must not enter the upstream original-samples kit.

Native iOS selection, VoiceOver/other screen readers, physical phone/tablet ergonomics, actual e-ink hardware, literary proofreading against underlying scans, and reader learning remain untested. Source-shape mode intentionally scrolls locally at enlarged sizes; assess whether real readers prefer uniform type. Low-resolution source pictures cannot acquire detail through enlargement. The source’s print year remains unverified.

The [source EPUB](https://www.gutenberg.org/ebooks/28885.epub3.images) is provided as a clearly labelled external source-edition download. The kit does not generate EPUB or synchronize web annotations with e-readers. Future export must handle images/captions, shaped verse and alternates, smallcaps/emphasis, source corrections, page links, navigation, licences and stable edition/annotation mapping. Current illustrated bundles require this project adapter; upstream v0.4.0 should reject the extra fields.
