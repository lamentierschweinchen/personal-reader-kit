## Dispositions after source and browser review

- **Edition adapter — implemented locally.** All 50 Ruskin and 168 Crane image placements preserved with larger source originals when available; all 1,025 internal source links resolve. Nested index text and a loose note marker needed general container handling. Independent Python HTML parsing confirms the complete body and license text after stated whitespace/page-label rules. This is edition-specific preparation, not a stock importer defect.
- **Meaningful verse geometry — implemented locally.** Crane’s `.i10` actually means 9.5em in the digital CSS; Ruskin’s attribution uses 16em inline padding. Replacing those with guessed leading spaces would be inaccurate. The named profile carries line insets independently from characters and supplies a group-level wrap/source-lines switch. A future reviewed shared layout contract could use this case; no upstream change made here.
- **Build output isolation — resolved locally; shared issue independently confirmed by the coordinator.** The inherited publication unit test called the default builder. Concurrent local test/dev builds were observed replacing the same dist directory and causing a missing-file read. This project now accepts `build({output})`; the publication test writes its own ignored output and asserts the served library bytes do not change. The coordinator reports the upstream fix separately. The customized build still exports its exact output list and complete `dist/library.json`.
- **Illustration sizing — resolved adaptation defect.** The first phone review of Crane’s front matter measured 535px document width at a 375px viewport: an inline intrinsic maximum overrode the viewport cap. Fitted images now use the smaller of source width and available width. Original-pixel enlargement is a deliberate, local scroll view. This was introduced by this project, not reported as a kit defect.
- **Direct study hydration — resolved adaptation defect.** A direct study URL could initially mount a source excerpt before built-in books were fetched. The custom study surface now waits for its required edition and supplies a failure state; all three direct routes are included in the browser journey. This is not evidence of a race in starter 7c9d60c.
- **Phone repeat layout — refined editorial choice.** The first rendered study placed the repeated result below all controls on a phone. The unit and live repeat now appear together, followed immediately by paired height/bend controls. This is a local design finding, not a kit feature request.
- **Trial fixture assumptions — adapted.** Original browser journeys address sample IDs and three old sample mechanisms. The new collection journey keeps the real contract checks while using the actual editions, source images, note links and studies. Original pure-contract suites remain regression evidence; their passing result is not editorial acceptance.
- **Runtime launch restrictions — environment only.** Local listening and macOS browser launch required sandbox escalation; bundled Playwright expected a different cached browser revision until explicit engine paths were supplied. No application dependency installation or kit change was needed.

The original-vector cover is sufficient for this collection. A reusable artwork workflow might help with provenance, crop/thumbnail review and source-free catalogue art, but these results do not justify a generator or mandatory cover-art pipeline. The two exact olive reproductions belong to reading/study context, not a generic promotional gallery.

- **Index hierarchy — implemented source adaptation.** Whole-text conservation did not by itself prove that nested subentries remained legible as children. Crane’s list depth is now explicit metadata and is included in the phone index review. This is a source-layout requirement, not a claim that the text-only importer supports nested historical indexes.

## Viewer acceptance repair

The coordinator found an actual adaptation defect at 1280×720: Fit image capped width but left the tall f020 raster at full height inside a shorter scrollport. The initial local flex repair also exposed an unconstrained `#dialog-content` wrapper; opening credits could enlarge the inner layout and scroll the caption away. Both are local viewer defects, not a kit importer claim.

The viewer now constrains the complete dialog wrapper, allocates image space after the real header, caption, controls and source-detail disclosure, and fits by the smaller width/height ratio capped at intrinsic pixels. ResizeObserver recomputes the fit for viewport/caption allocation changes. Original pixels and deliberate zoom use local pan/scroll. The visible caption stays at least 14px; verbose source credit remains recoverable in a bounded disclosure. Fit percentage reports the actual scale.

Current delayed-library loading is tested as pending, not a missing illustration. A synthetic unresolved image reference produces an explicit recovery message after loading. The coordinator’s brief old-cache incident was not reproduced on the current renderer; it is not recorded as a confirmed current or upstream defect.
