# What is public and what stays with you

The default site contains application code and two original sample works. Adding a book reads it with the browser File API and saves it to that browser's IndexedDB. Notes, reading places, preferences and spoiler boundaries are also in IndexedDB. No import or annotation request is made to a server. The application has no analytics, remote fonts, third-party scripts or map requests.

This is local browser storage, not encrypted vault storage. Someone using your browser profile or compromised same-origin code may access it. The host serves the application and may keep ordinary access logs. Extensions and the device's security remain relevant. Do not imply the repository's private setting or the application's noindex header is access control.

The application and original samples are cached for offline use. Imported books stay in IndexedDB, outside the public service-worker manifest. Browsers can evict or clear both stores. The offline indicator verifies the application cache; it is not a backup or a promise of indefinite retention. Keep original files and export a private reading bundle. The bundle contains selected full editions, exact quotations and personal comments and belongs somewhere private.

The separate **Export original recovery data** action also includes full local book records and archived damaged states. Keep this raw recovery file private and give it only to an authorized repair workflow. A damaged book record does not remove healthy books. An unreadable state can be repaired from a validated backup through Settings: archive and replacement commit atomically, preserving local books. Failed repairs leave the original unchanged. A stale repair cannot overwrite already readable state. Without a valid backup, retain the raw export and use an authorized repair workflow; there is no automatic reconstruction of unknowable records. Unsaved connection drafts survive navigation within the current tab and can be exported; they are not crash recovery or cross-device synchronization. Closing an edited note asks before discarding it.

Automatic device sync is not implemented. On a second device, restore a **private reading bundle**, or import exact prepared editions and restore a separate annotation backup. Current-device places are retained and missing places are recovered; spoiler boundaries remain explicit on that device. Opening an installed web app may use a different browser storage area than a tab, depending on the platform.

Never commit personal source, conversions, extracts, annotation fixtures, screenshots, intake notes, keys or configuration. Use ignored `.reader/` for local agent work, but remember that ignores do not scrub past commits. The public audit rejects shallow/partial clones and concealed-history views, records its HEAD/ref scope, and checks all commits reachable from those local refs and the exact index/working files. Review the complete history before pushing. If private material was committed, stop publication and repair the boundary; deleting it in the next commit is insufficient.

To host books themselves, implement and test real access control first. Every raw asset, download, source map, alternate domain, preview, old deployment and content API needs the same policy. Client-side hiding and passwords embedded in JavaScript do not protect a static book URL. Do not cache private hosted responses in a public worker without a separate authenticated-cache design. See [deployment](DEPLOYMENT.md).

## The site address is part of the library

IndexedDB belongs to the origin (scheme, host and port), browser profile and device. Localhost, a preview URL, the canonical domain and a replacement domain have independent libraries. An empty shelf at a new address does not mean the old records were erased. Choose the canonical domain before substantial importing. Export a private bundle with the exact editions and records, restore and verify it at the destination, then retire the old address. Keep both raw originals and prepared editions: a later conversion of the same source can alter anchors. See the [migration procedure](DEPLOYMENT.md#choose-an-address-and-move-without-losing-your-library).

The public shell is a software trust boundary. Future code served at the same origin can read that origin’s books and annotations, even though this version has no upload endpoint. Choose a host and update process you trust, review changes, and keep private backups before upgrades. Offline caching is not protection against a malicious future update.

The agent that prepares your books has its own processing boundary. Giving a file to a cloud-backed agent may send text to its model provider. Check that before supplying material; do not infer on-device AI processing from this app’s browser-local storage.

Bundles are unencrypted, even when their checksum passes. A checksum detects accidental change; it cannot authenticate a file or make a shared download private. All saved records are included even if you select only some editions, so quotations from unchecked books remain sensitive. Drafts, damaged records and quarantine archives need separate exports. The restore preview requires explicit confirmation, refuses conflicting edition content and leaves both stores unchanged on failure. A bundle is a backup/transfer artifact, not automatic synchronization.
